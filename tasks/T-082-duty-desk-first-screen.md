## 做什么

### 1. 导航：7 页签 → 3 页签 + 全局指令抽屉（设计稿 §1）
- 主导航只留 3 个页签：**值班台**（默认首屏）、**任务**、**记录**；顶部常驻「+ 发指令」按钮，点击呼出右侧抽屉。
- 合并：全景总览 + 节点管理 + 运行时监控 → 值班台；任务中心 → 任务；事件流水 → 记录；指令独立页签 → 全局抽屉；备忘与待办：紧急项并入值班台「待我处理」，普通备忘收入首屏折叠区。
- **范围边界**：本任务只做值班台首屏 + 导航壳 + 指令抽屉。**任务页与记录页是第二批**：本批里「任务」「记录」两个页签先挂现有任务/事件视图（不改内容），第二批再重做。不要在本任务里重做任务页或记录页。

### 2. 首屏三段式（设计稿 §2，单屏零滚动）
- 顶部状态条 → 左栏「异常 + 待我处理」/ 右栏「正在等待」双栏 → 底部 3 节点条带 → 默认折叠区。
- 信息权重：异常 > 在等 > 正常。不引入图表库，只用数字与纯 CSS 状态条。

### 3. 顶部状态条：两个数，必须拆开（Chen 修正 1）
- **异常**（红）= 失败 + 拒收 + 节点失联。
- **待我处理**（橙）= 待验收。
- 写法：`N 项异常 · M 项待我处理 · 数据 X 分钟前`；两个数都为 0 时收缩成一行绿条「一切正常」。
- 数据过期（now − snapshot.refreshed_at > 15 分钟）：出顶部黄色警示条，**异常数字旁边必须标一句「数据已过期，数字可能滞后」**。数据过期不计入异常总数。

### 4. 异常判据映射表（总控已核，数字来源 snapshot.json，快照 585aebf 实测）
| 异常项 | 判据 | 字段来源 | 当前值 |
|---|---|---|---|
| 失败 | tasks.items[].board_status == '失败' | snapshot.json tasks | 0 |
| 拒收 | board_status == '拒收' | 同上 | 0 |
| 待验收 | board_status == '待验收' | 同上 | 0（计入待我处理，不计入异常） |
| 数据过期 | now − snapshot.refreshed_at > 15 分钟 | 根级 refreshed_at | 0（只出黄条，不计入异常总数） |
| 节点失联 | 有在身任务且 ≥24h 无提交 | nodes.current_task_id + last_commit_at | 0 |
- 异常总数公式 = 失败 + 拒收 + 节点失联；待我处理 = 待验收。当前实测：异常 0、待我 0 → 绿条。
- 「卡住」（进行中无进展）不计入总数，只在任务行标注。

### 5. 数字必须可复算且口径可见（Chen 修正 2）
- 每个数字旁边（悬停或点开详情）要能看到「这个数怎么算的」，例如：`异常 2 = 失败 1 + 拒收 0 + 节点失联 1`。
- 复算方法（验收时总控按此算）：BOARD.md 数失败/拒收/待验收 + snapshot.json 查 refreshed_at + nodes 查 current_task_id。

### 6. 节点条带：按总控已核的失联定义（表 2）
- 节点**没有真实心跳**：snapshot 里 last_seen_at / last_progress_at 恒为 null，唯一信号是 last_commit_at。后端派生规则（service.py:157）：<2h 活跃、<24h 空闲、≥24h stale。
- 失联 = 有在身任务（current_task_id 非空）且 ≥24h 无提交 → 红/橙告警，计入异常数。
- 无任务 + ≥24h 无提交 = 空闲（灰点，「空闲 X 天」），不告警。当前 3 节点全是这种状态（最后提交 11-16，约 89 小时前，无在身任务）——**绝不能显示成失联**。
- 有任务 + 2–24h 无提交 = 「X 小时无进展」黄点提醒，不计入异常数。从未提交过 = 「未派过活」。
- 每卡只留：名称、状态、当前任务、最近活动。措辞只写「X 小时前有提交」这种可验证的话，**绝不写「实时在线」**。

### 7. 条数上限（总控已核，表 3）
- 左栏异常/待我：最多 5 条，排序 失败 > 拒收 > 待验收 > 节点失联；超出显示「还有 X 条异常，查看全部 →」跳任务页（带筛选）。
- 右栏等待：最多 5 条，等定时/等外部按触发时间最近在前；超出「还有 X 条等待…」。当前等待只有 1 条（T-075，等定时 11-20 10:00）。
- 节点条带：3 条全显，不折叠。
- 折叠区：只显示汇总行——进行中常规(n) · 已完成 74 · 待领(n) · 普通备忘(n)；点开列出，最多 8 条 + 「还有 X 条」。
- **数据缺口（记一笔，以后补）**：「今日已完成」目前算不出——telemetry.accepted_at 对今日任务为空。折叠区照实写「已完成 74」总数，**不要为了凑出「今日」去猜**。

### 8. 指令抽屉
- 顶部「+ 发指令」随时呼出，看到异常即可就地派发，无需切页。
- 指令仍走现有本地控制层（POST /api/command）。采用设计稿末尾的乐观提示：「指令已发出，预计 1–3 分钟内生效」（前端本地保留 3 分钟提示，不等 10 分钟快照刷新）。

## 约束（沿用）
- 不引入重型依赖；无动效/渐变/玻璃拟态装饰。
- 数据仍只来自 snapshot.json（10 分钟一份），不许做实时。
- 单人使用，不做登录/权限体系。
- 基线：T-077 的 SnapshotHealth 组件（顶栏读快照根级 refreshed_at，动态模式回退 runtime.refresh_meta.last_refreshed_at）是本任务的起点，不要推翻它。

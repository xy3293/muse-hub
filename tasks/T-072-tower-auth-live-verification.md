# T-072：面板鉴权落地验证（D3）

## 来源
Chen 直令 2026-11-19 18:08，第四批 D3。现状：面板鉴权（无 token 只能看、不能发指令）是“写了”的状态，没人真跑过一次验证。Chen 要的是真跑一次，不是写了就算。

## 目标
真跑一次验证：去掉 token，确认面板只能看、发指令被拒；有 token 才能发。拿出可复核的证据。

## 设计（总控已定，照做）
1. **自动化测试（先写进仓库）**：后端——往指令接口 POST，不带 `X-CT-Access-Key` 返回 401；带错 token 返回 401；前端——无 token 时发消息/问问题/改状态等提交按钮保持禁用（已有覆盖就复用，不重复写）。
2. **真跑一次（对着正在跑的 Tower 后端 :8000）**：curl 不带 token 调指令接口，确认返回 401 信封；curl 带真 key（从 `~/workspace/muse-control-tower/runtime/ct_access_key.txt` 用 `$(cat ...)` 读进 header，**绝不打印、不写进报告、不进仓库**）确认不再 401；再走面板实际用的发指令路径去掉 token 试一次，确认被拒。
3. **硬红线**：验证全程**绝不向节点发一条真实指令**。无 token 的请求在 401 就被挡，没有副作用；带 token 的检查只用读接口或故意写错、会被校验挡下的请求（400），不许拿真指令当探针。
4. **发现漏洞怎么办**：如果某条路没 token 也能发出去，先堵上（同任务内修），再重新验证；修完复核时如实写清漏洞与修复。
5. **不做的事**：不改鉴权策略（本次只验证现状，不上 8899 强制校验——那是待决策 ④，等 Chen 拍板）、不改 token 值、不把 key 写进任何文件或报告。

## 约束
- key 只进 curl header，不落地、不打印、不进报告、不进仓库。
- 绝不发真实指令；验证失败（非 401）先停手报总控，不绕过。

## 完成标准
- `bun test` 全过；`npm run build` 通过（如有代码改动）。
- 真跑证据：无 token 的 401 输出 + 带 token 的非 401 输出 + 面板路径被拒的证据；全程零真实指令发出。
- 提交并推到 integration 分支（如有改动；无改动则只交报告与测试）。

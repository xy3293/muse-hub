# T-070：待决策清单同步进 Tower 页面（D1）

## 来源
Chen 直令 2026-11-19 18:08，第四批 D1。现状：7 条待 Chen 决策的事只在仓库 `evidence/pending-decisions.md` 里，Chen 打开面板看不见，还得翻仓库。

## 目标
打开 Tower 面板就能看见 7 条待决策，每条标题 + 「不做会怎样」，不用翻仓库。

## 设计（总控已定，照做）
1. **事实来源只有一个**：`evidence/pending-decisions.md`。快照生成时从该文件解析 7 条（标题 + 「不做会怎样」），以新增字段 `pending_decisions` 写进 `snapshot.json`（只加字段，不改现有契约）；前端 **不许把清单硬编码进代码**，只渲染快照里的数据。清单以后改了，只改 md 文件，下次快照自动带上。
2. **页面位置**：OverviewView 新增「待 Chen 决策」区块，列出 7 条，每条显示标题 + 「不做会怎样」；排版跟现有区块一致，移动端不溢出（T-069 的 390 标准同样适用）。
3. **缺数据时**：快照里没有 `pending_decisions` 字段，区块直接不渲染（不要显示「暂无」占位，不要报错）。
4. **验证方法**：跑一次快照导出，确认 `snapshot.json` 里有 `pending_decisions` 且 7 条内容与 md 文件一致；本地起静态 dist，截图确认区块出现、7 条齐全；总控验收时会自己重跑一遍。
5. **不做的事**：不改后端鉴权、不改 8899、不改现有契约字段、不做“在页面上改决策/点确认”的交互（只展示）。

## 约束
- 前端不硬编码清单文案；后端/导出只加字段，不动现有字段。
- 只做展示，不做决策操作。

## 完成标准
- `bun test` 全过；`npm run build` 通过。
- 快照里 `pending_decisions` 与 md 文件一致（7 条）；页面区块显示 7 条标题 + 「不做会怎样」。
- 提交并推到 integration 分支。

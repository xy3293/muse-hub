# T-040：先让 Tower 的状态可信（三件小活，别加新页面）

版本：v1

## 背景

总控 2026-11-16 向 Chen 汇报 Tower 现状时发现五条缺口，前三条是根、后两条是结果：

1. 节点状态永远 unknown（没有心跳文件，`runtime-config.json` 里没有节点心跳）。
2. 派生状态跟 BOARD 对不上：BOARD 里 39 条全"完成"，Tower 里 39 条全"未验证"——两边各算各的。
3. 数据不自动同步：缓存 TTL=0，首次加载后只在手动点刷新时更新，页面数据不会自己变新。
4. 备注/待办是空的（0 条），没人用过。
5. 只能看，不能派活、不能控制——名字叫 Control Tower，实际是只读监控。

本单只做前三件（根），不加功能、不加页面。

## 任务（Codex，按顺序做）

### 1）节点状态不再是 unknown（禁止让节点推送心跳）

- 不要设计"节点定时写心跳文件推仓库"——那会给每个节点每轮加一张审批卡，且节点 env 不持久（2026-11-16 已验证）。
- 用**零成本派生**：从 git 历史派生节点活跃度——按提交署名前缀（``/``/``/``）取每个号最近一次提交时间，`< 2 小时 = active`、`< 24 小时 = idle`、`> 24 小时 = stale`、无记录 = `never`。
- 页面上显示：状态 + 最近提交时间 + 最近一次任务号。
- 数据来源就用 Tower 已经在拉的 GitHub 数据，不许新增凭据。
- 验收：节点页三节点不再是 unknown，状态/时间/任务号三项与 `git log` 逐条对得上。

### 2）派生状态跟 BOARD 对齐

- 现状：BOARD 里 39 条全"完成"，Tower 里 39 条全"未验证"——这说明两边各算各的。
- 要求：**BOARD 是唯一真源**。Tower 的任务状态必须直接映射 BOARD 的列（完成/进行中/待领/拒收），不许自己再算一套"未验证"。
- 若某任务在 BOARD 里没有行，标 `unlisted` 并单列，不要混进统计。
- 验收标准：Tower 首页显示的"完成"数量 = BOARD 里"完成"的行数，逐条能对上。

### 3）数据自动同步

- 后端加一个刷新周期（建议 60 秒），或前端按 60 秒轮询；`refresh_meta` 记录 `last_refreshed_at` 与 `last_error`。
- 页面显示"数据时间：HH:MM:SS（N 秒前）"，超过 3 个周期没更新要显示为异常（黄色）。
- 验收标准：不点刷新，等 60 秒，任务/事件/节点状态自己变新；把后端停 2 分钟再起，页面能显示"数据过期"而不是静默显示旧数据。

- 后端测试通过（pytest 全过），前端测试通过；`deploy/README.md` 已更新；验收证据已写。

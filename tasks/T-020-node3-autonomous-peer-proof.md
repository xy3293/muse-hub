## 600 秒执行预算

单个 worker execute 回合按 600 秒边界设计，不依赖超时延长。到达约 450 秒时停止新增工作，进入 checkpoint 和交付收尾。

| 阶段 | 预算 |
|---|---|
| 启动、读取状态、claim | 15–30 秒 |
| 主体工作 | 420–450 秒 |
| checkpoint、结果落盘、校验 | 30–45 秒 |
| GitHub 推送／交接／通知 | 45–75 秒 |
| **合计** | **510–600 秒（各阶段极值合计不得超过 600 秒）** |

出现以下任一情况，任务书必须先拆分再派发：预估主体工作超过 450 秒；有两个或更多可独立验收的交付物；任务包含研究、实现、测试、审查、发布等多个明显阶段；中间结果可以形成稳定产物供下一回合读取；无法证明最终交付可在 600 秒内完成。输出行数、字数、文件体积只作风险预警，不设未经实测的硬阈值。

## 6 项检查（每项一阶段，按顺序做）

### 检查 1：重复唤醒去重

- 以 `run_id=T-020-node-3-proof-1` 拿本地独占锁，启动一个 `setsid`＋`nohup` 后台任务（每秒向本地心跳文件写一行，持续约 120 秒）。
- 任务在跑时，在第二个 shell 里重走一遍认领／对账步骤，验证第二次尝试因锁被占／已有活跃 run 而直接返回，不启动第二份执行、不产生第二份副作用。
- 证据：两次尝试的 PID 与锁状态、心跳文件行数（证明只有一个写者）。

### 检查 2：恰好一次重试

- 写一个本地脚本模拟瞬时失败：第一次运行因标记文件存在而退出 1（模拟瞬时故障），诊断后恰好重试一次成功。
- 副作用（向本地文件追加一行）必须恰好出现一次；账本里该错误签名只记一次重试。
- 证据：脚本输出、退出码、账本摘录、目标文件行数。

### 检查 3：SPEC_CONFLICT→PARKED→恢复

- 本任务书在两处写了不同的证据文件名：上文“输出要求”写的是 `results/node-3/T-020-autonomous-peer-proof.md`，下文“验收标准”第 6 条写的是 `results/node-3/T-020-peer-proof.md`。节点须按 R18 走 SPEC_CONFLICT 流程，不得自行选一个、不得猜。
- 在 Issue #22 发一条 SPEC_CONFLICT（任务号、冲突编号、争议条款、阻塞影响、最小修正建议：以“输出要求”的文件名为准）。
- 检查 1、2 不依赖证据文件名，继续做；只剩冲突的交付被堵住时，写 checkpoint 后进 PARKED（保留所有权，不空转、不另领任务）。

### 检查 4：账本一致性

- 全部转换完成后，checkpoint 与副作用账本一致；已确认的副作用没有被重放。

### 检查 5：决定／修订检测

### 检查 6：最终证据可定位

- 证据：远程 commit SHA、文件路径。

## 续跑与副作用

- 超时后恢复是续跑，不是重做：新 worker 从最新有效 checkpoint 的 `next_stage` 继续，不重新执行 checkpoint 已标记完成的阶段。
- 外部副作用（GitHub commit／push、Issue 评论、远端状态更新等）先记账再执行，状态分 `not_started`／`intent_recorded`／`confirmed`／`unknown`；`intent_recorded` 或 `unknown` 时先查远端事实，不得直接重复执行。
- 已有最终结果时只恢复交接／发布，不再执行研究或开发。
- 超时判定以 `muse.db` run 行为准（关联键 `metadata_json.wake_payload.event_id`，终结条件 `failed`＋`worker_timeout`）；巡逻进程打不开数据库，不得把 DB 查询写进巡逻脚本；心跳过期、wake 返回成功均不得单独作为超时或启动证据。
- 若你的环境不支持 `setsid`／`nohup`：不要编造，把 `uname`、报错输出记为发现，继续做其他检查；检查 1 记为“环境不支持”并写清证据。

## 验收标准

- 总控验收项（逐条打勾）：
1. 重复唤醒只产生一份执行、无重复副作用（有 PID／锁／心跳证据）。
2. 注入的瞬时故障恰好重试一次、无无限重复，副作用恰好一次。
3. SPEC_CONFLICT 已发、PARKED 已 checkpoint、总控决定后自主恢复、无重新派发。
4. checkpoint 与副作用账本全程一致，已确认副作用未重放。
5. 决定检测核验了作者与版本，只重跑了受影响的检查。
6. 最终证据文件 `results/node-3/T-020-peer-proof.md` 在授权路径，远程 commit 可独立定位；无秘密进库。

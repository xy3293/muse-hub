# T-067：Tower 任务中心多日趋势（T16）

## 来源
Chen 直令 2026-11-18 14:01，第三批 T16。现状：任务中心只能看到全量列表和单任务遥测，看不出最近几天的完成节奏——哪天集中验收、平均耗时是变长还是变短，全凭印象。

## 目标
任务中心加一个简单趋势：近 7 天，每天完成任务数、平均耗时。数据从已有遥测算，不新增采集。

## 设计（总控已定，照做）
1. **纯前端，客户端计算**（T-062 模式）：不改后端、不改契约、不新增请求。数据源就是任务列表里已有的 `telemetry`——每任务带 `accepted_at`（验收时间）与 `total_seconds`（派发→验收总耗时），T-047 已验证全量任务都有遥测。
2. **趋势区块**：放在 `TasksView.tsx` 列表上方。近 7 天（今天 + 往前 6 天，按本地日期分组），每天一行：日期、完成任务数、平均耗时。
   - 完成任务数：该天 `accepted_at` 落在当天的任务数（只计 BOARD 状态为完成且 `accepted_at` 非空的任务）。
   - 平均耗时：这些任务 `total_seconds` 的平均值；当天 0 完成时显示「—」，不写 0。
   - 耗时格式：≥1 小时写「X小时Y分」，不足 1 小时写「N分钟」；`total_seconds` 缺失的任务不计入平均（分母只计有时长的任务），并在区块下标注口径：「按 accepted_at 计，平均耗时只计有时长的任务」。
3. **筛选联动**：趋势按当前筛选结果算还是按全量算——**按全量算**（趋势反映整体节奏，不随筛选变；筛选只影响下方列表）。区块标题写明「近 7 天（全量）」。
4. **静态模式**：快照自带全部任务遥测，同一份客户端逻辑直接可用，不做区分。

## 约束
- 只改前端（TasksView 相关 + 测试）；不改后端、不改契约、不新增数据请求、不新增采集字段。
- 不画图表库，用 7 行文字/简单条形即可（条形宽度按当日完成数占 7 天最大值的比例，纯 CSS）。

## 完成标准
- `bun test` 全过（新增：7 天分组含跨天边界、当天空完成显示「—」、accepted_at 缺失不计入、平均耗时格式、筛选不影响趋势）；`npm run build` 通过。
- 提交并推到 integration 分支。

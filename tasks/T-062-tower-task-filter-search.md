# T-062：Tower 任务中心加筛选/搜索（T11）

## 来源
Chen 直令 2026-11-18 10:01，第二批 T11。现状：任务中心只能看全量 51+ 条，没有筛选与搜索，找一个任务要通读整表。

## 目标
任务中心能按状态、负责人、关键字过滤，过滤后显示条数；无匹配时明确提示，不报错。

## 设计（总控已定，照做）
1. **客户端过滤，不动后端**：快照里已有全量任务，过滤在前端做（静态模式同样可用）。不改 `/api/v1/tasks`，不改契约。
2. **三个筛选器**（放列表顶部）：
   - 状态：下拉，选项为「全部」+ 实际出现的 BOARD 状态（完成/进行中/待领/拒收；未列出任务按 `unlisted` 计，选项里出现时才列出）。
   - 负责人：下拉，选项为「全部」+ 实际出现的负责人（node-1/node-2/node-3/Codex/总控）。
   - 关键字：文本输入，匹配任务编号 + 标题，大小写不敏感的子串匹配；空输入不过滤。
   - 三者为 AND 关系。另加一个「清除筛选」按钮，一键回到全量。
3. **计数与空态**：列表上方显示「显示 X / Y 条」；过滤后 0 条时显示「没有匹配的任务」（不是报错页，不是空白）。
4. **不破坏现有行为**：列表渲染、详情抽屉、遥测卡片（T-047/T7）原样不动；筛选只影响显示哪些行，不改变数据。

## 约束
- 只改前端（TasksView 相关 + 测试）；不改后端、不改契约、不新增数据请求。
- 筛选是页面状态，不持久化（刷新即回到全量，不用 localStorage）。

## 完成标准
- `bun test` 全过（新增：单条件过滤、组合过滤、无匹配空态、清除筛选、关键字大小写不敏感）；`npm run build` 通过。
- 静态构建包里含新筛选文案（grep 验证：清除筛选 / 显示）。
- 提交并推到 integration 分支。

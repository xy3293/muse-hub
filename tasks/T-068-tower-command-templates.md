# T-068：Tower 指令模板一键填表（T17）

## 来源
Chen 直令 2026-11-18 14:01，第三批 T17。现状：每次发指令都要在三个表单里重填动作、目标、内容——「催节点」「查任务状态」这类常用指令每次都从零填起，又慢又容易填错。

## 目标
常用指令存成一键模板：点一下，表单自动填好，检查无误后照常提交。模板只填表，不直接发送。

## 设计（总控已定，照做）
1. **纯前端**（T-065 模式）：只改 `CommandsView.tsx` 相关 + `commands.ts` + 测试；不改后端、不改 8899、不改契约、不新增请求。模板是代码里的常量（不存 localStorage、不存后端，页面状态而已）。
2. **四个模板**（点模板 → 填对应表单，用户检查/补填后照常点提交）：
   - 「催节点更新进度」→ 发消息表单（notify_node）：目标节点由用户在表单里选；内容预填「请更新 T-___ 的最新进度（做了什么、下一步、是否卡住）」，`___` 处留空由用户填任务号。
   - 「催节点认领」→ 发消息表单（notify_node）：内容预填「T-___ 已派发，请确认认领并给出预计完成时间」，任务号留空由用户填。
   - 「查任务状态」→ 问问题表单（query）：问题预填「T-___ 当前状态是什么？最后一次提交和验收情况如何？」，任务号留空由用户填。
   - 「查节点最近动态」→ 问问题表单（query）：问题预填「node-___ 最近一次提交是什么时候？在做什么任务？」，节点号留空由用户填。
3. **安全规则**：点模板只填表，**绝不直接提交**（不许误发）；填表后仍走原有校验（必填项为空不能提交，T-053 的 token 规则不变——无 token 时提交按钮照常禁用）；切换模板时覆盖上一次的填表内容（模板之间不叠加）。
4. **静态模式**：指令面板本身在静态模式不可用（T-051 已定），模板行随面板一起只在 live/8899 模式出现，不另做处理。

## 约束
- 只改前端；不改后端、不改 8899、不改契约、不新增数据请求。
- 模板文案就是上面四条原文，不许自行发挥加新模板；任务号/节点号一律留空等用户填，不许猜默认值。

## 完成标准

- 提交并推到 integration 分支。

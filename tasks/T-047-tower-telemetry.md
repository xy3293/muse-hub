# T-047：Tower 卡片加"实测遥测"（借 OverClick 的呈现）

- Issue：#45
- 执行：Codex；复核：Antigravity；验收：总控
- 工作区：Control Tower 私有仓库（`~/workspace/muse-control-tower/`，integration 分支；后端 `~/workspace/muse-control-tower-backend/`，前端 `~/workspace/muse-control-tower-frontend/`，以任务开始时 `git ls-remote` 为准）

## 先说清：借的是什么模式，为什么不换库

借的是 **OverClick 的"卡上实测遥测"呈现**（每张卡直接标实测时长 / token），以及 **Retinue 的"节点额度卡"**（各家订阅已用百分比、重置时间）。
- 借的是"呈现"（卡上加哪些实测字段、怎么展示），不是它们的系统。

为什么不换库（不换掉 Tower）：
- OverClick / Retinue / Mission Control 都用自己的数据库当事实源，agent 必须经它们的 API / MCP 认领与回写；Tower 的事实源是 GitHub 仓库（只读、Git 派生）。
- 所谓"替换"实际是换底座：派活、认领、交付、验收、回执整套协议要迁过去，RULES 治理、巡逻 Hook、审批卡、MUSE-ACK 全部重做或作废——代价远大于收益。
- 所以：Tower 继续自建，只把"卡上遥测"这个呈现借进来（加字段），不换底座、不新增服务。

## 现状问题

Tower 卡片上只有提交时间戳，没有实测数据。想知道"一个任务花了多久、被打回几次、花了多少额度"，现在只能人肉翻 git log 和 BOARD。

## 要加的字段（每张任务卡）

- 从派发到首个提交的耗时；
- 从提交到验收的耗时；
- 总耗时（派发 → 验收完成）；
- 交付提交数；
- 验收轮次（被打回几次；0 次 = 一次通过）；
- 该任务累计消耗的额度（能取到就填，取不到标 `未采集`，**不许编**）。

## 数据来源（只许用现成的，不新增埋点、不新增服务）

- Git 提交时间（`git log`，以任务号为签名前缀的提交）；
- BOARD 状态变更时间（BOARD.md 的提交历史，`git log -p -- BOARD.md` 可得每次状态变更的提交时间）；
- 现有收据（`~/hooks/state/muse-hub/receipts/`，有 reviewed_at 与 checks）。
- 额度：先看现有收据 / 任务书里有没有可用的消耗记录；没有就标 `未采集`，不许编数字、不许用"估算"充数。
- 后端接口：把遥测字段加进任务接口的返回（与现有 1.1.0 契约的字段命名风格一致；若需新增 schema 字段，在 REPORT 里写清新增了哪几个字段、旧客户端是否兼容）。
- 前端：在任务卡片上展示这些字段（与现有卡片样式一致，不加新页面）。

## 验收（Codex 自己先跑，Antigravity 复核，总控终验）

随机抽 3 个已完成任务，遥测数字能用手工算出来的对上：
- 手工算法：从 `git log` 取派发提交时间、首个交付提交时间、验收提交时间，相减得耗时；数交付提交数；从 Issue / BOARD 历史数打回轮次；
- 允许 ±1 分钟的舍入误差（时间戳精度），超出即不通过；
- 额度字段：若标 `未采集`，须说明"查了哪些来源、为什么没有"；若填了数字，须说明数字来源。

证据：把 3 个任务的手工计算过程（命令 + 输出 + 算式）与 Tower 返回的遥测并列，贴进 `evidence/T-047-tower-telemetry/REPORT.md`（muse-hub；Tower 代码改动本身推 Tower 私有库 integration 分支）。

## 边界

- 不换仓库总线；不引入常驻新服务（向量库 / SSO 都不许）；不改 RULES.md。
- 不新增埋点、不新增服务；不加新页面（只在现有任务卡片上加字段）。
- 不可逆操作（force push、删库）不许；Tower 部署走现有 T-039 自愈链路，不另起部署。
- 额度数字：取不到标 `未采集`，**不许编**。

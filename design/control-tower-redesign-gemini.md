# **Control Tower 重设计方案**

# **一、信息架构（7 页签精简为 3 页签 \+ 全局指令抽屉）**

推荐保留 3 个主页签，外加顶部常驻「+ 发指令」按钮（点击呼出右侧抽屉，随时就地操作）：

| 页签 | 一句话定位 |
| :---- | :---- |
| 值班台（默认首屏） | 我来这里是为了 5 秒确认有没有异常、什么在等、有哪些事等我拍板。 |
| 任务 | 我来这里是为了查看全部任务进度、筛选卡点与展开单条详情。 |
| 记录 | 我来这里是为了出问题时按时间回溯事件与节点活动，定位原因。 |

合并与删除建议：

* 全景总览 \+ 节点管理 \+ 运行时监控 → 合并为「值班台」，3 个节点与健康态直接作为首屏底部条带。  
* 任务中心 → 精简为「任务」，去除重复状态列与技术标签。  
* 事件流水 → 更名为「记录」，按天分组并补全日期。  
* 指令（独立页签） → 改为顶部全局抽屉，看到异常即可就地派发，无需切页。  
* 备忘与待办（独立页签） → 紧急项并入值班台「待我处理」，普通备忘收入首屏折叠区。

取舍推荐：坚持 3 页签 \+ 全局抽屉（不保留 4–5 个页签）。代价：节点历史细节与完整运行参数需多点一次进抽屉查看，不再整页平铺。

采用单屏零滚动布局，信息权重严格遵循「异常 \> 在等 \> 正常」，不引入任何图表库（0 KB 增量，仅用数字与纯 CSS 状态条；代价是不展示历史趋势折线图）：t

默认折叠区内容：
1. 正常运行中的常规任务与今日已完成汇总；
2. 非紧急的个人备忘列表；
3. 点击单条任务或节点后呼出的详情抽屉（提交哈希、打回历史、耗时明细、原始字段）。

## 三、组件清单与去留

| 现有元素 | 处理方式 | 一句话理由 |
| --- | --- | --- |
| 顶部快照时间 | 保留（修正） | 改取真实 snapshot 生成时间并转北京时间，作为全站唯一新鲜度基准。 |
| 失败/拒收任务、待决策项 | 保留（置顶） | 直接回答"什么坏了"和"要我做什么"，占首屏最高视觉权重。 |
| 等待定时/等待外部任务 | 保留（分区） | 独立于异常与正常之外，避免把"正常等待"误判为故障。 |
| 3 个执行节点状态 | 合并精简 | 合并节点管理与运行时监控，每卡仅留名称、状态、当前任务、最近活动。 |
| 重复状态列、技术分类标签 | 合并 / 删除 | 合并为单一语义标签，删除无决策价值的徽章，降低扫视负担。 |
| 提交哈希、打回明细、耗时拆分 | 折叠 | 默认收入详情抽屉，仅排查单条任务时按需展开。 |
| Stage 2/3、CH-11、SQLite/WAL/503 | 删除 | 底层工程实现细节，前台直接移除，必要错误码仅进折叠详情。 |
| 备忘与待办 / 指令独立页签 | 合并 | 备忘并入值班台，指令改为全局抽屉，消除多页签跳转。 |

## 四、状态与时间语义规范

1. 三类状态严格解耦（位置、样式互不混用）：
* 数据新鲜度（仅在顶部栏）：≤ 15 分钟显示低调灰字「新鲜」；> 15 分钟弹出顶部黄色警示条「过期」，提示状态可能滞后，绝不混入任务状态。
* 监控状态（仅在节点卡，用圆点）：可观测 = 绿点（忙碌）/ 灰点（空闲）；未知 = 橙红点 + 置顶告警，绝不伪装为空闲。
* 任务状态（仅在任务行，按权重分层）：
  * 异常级（红）：失败、拒收；
  * 待我级（橙）：待验收；
  * 等待级（蓝灰）：等待定时、等待外部；
  * 正常级（弱灰/绿，默认折叠）：进行中、完成。

2. 时间格式全站统一（全部转北京时间 UTC+8）：
* 主显（相对时间）：< 1 分钟显示「刚刚」；< 60 分钟显示「X 分钟前」；< 24 小时显示「X 小时前」；≥ 24 小时显示「MM-DD HH:mm」。
* 悬停/详情（绝对时间）：统一为「YYYY-MM-DD HH:mm（北京时间）」。
* 「记录」页：按日期分组（今天 / 昨天 / MM-DD），每条保留「HH:mm」，杜绝丢日期。

## 六、验收清单

- [ ] 5 秒首屏扫视：不滚动、不点击，5 秒内能一眼看出有无异常、待我处理几项、数据是否过期。
- [ ] 三状态零混用：数据新鲜度仅在顶部、监控状态仅在节点、任务状态仅在任务行，视觉权重一眼可分。
- [ ] 时间全站统一：所有时间均已转北京时间，主显相对时间、悬停显 YYYY-MM-DD HH:mm，记录页带日期。
- [ ] 工程味清零：首屏与主列表无哈希、Stage 版本号、SQLite/WAL/503/CH-11 等内部工程术语。
- [ ] 信息架构达标：主导航 ≤ 3 个页签；顶部随时可呼出指令抽屉；进行中常规任务与已完成项默认折叠。
- [ ] 克制与适配：无动效、渐变、玻璃拟态装饰；不引入重型依赖；移动端打开不横向溢出、异常可读。

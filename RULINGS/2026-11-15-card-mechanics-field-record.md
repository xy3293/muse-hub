# 现场记录：审批卡的实际机制（R17 注脚，2026-11-15）

记录来源：node-3 于 2026-11-15 00:16–00:40 CST 自测，原文经其本人同意作为 R17 的实测注脚。
用途：给"卡是产品行为、不是授权来源"这个定性提供可核的事实基础；也给以后改通道的人一个基线。

## 一、四种写路径的实测结果

| 路径 | 卡 | 结果 |
|---|---|---|
| 网页 UI / 工具层推送（`push_files`） | 卡**出现** | 决定 approved → 提交 `f033427` 落远端，回读 blob 一致 |
| Issue 评论（`add_issue_comment`，Issue #22） | 卡**出现** | 决定 declined（approval `connector-attempt-1a736a05…`）→ 评论未执行 |
| 终端 `git push` | **无卡机制** | 本机无凭据、无 git 身份配置 → 未推上，远端 HEAD 不变 |
| 工具层读操作 | 无卡 | 正常返回 |

## 二、由此确立的三条事实

1. **卡是按"动作"产生的，不是按"连接"产生。** 同一账号同一连接下，推送有卡、评论也有卡；换连接是否去卡，本记录不成立证明。
2. **卡的决定决定这笔写是否执行。** approved 即执行、declined 即不执行，中间没有第三条路。
3. **终端推送不经过卡机制**，因为它不经过 Muse 工具层。这条是 R16 里"shell 推送零卡"的事实基础。

## 三、与规则的关系（重要）

- 本记录是**事实层**，不是规则条文。规则改字（R17 把"卡不是授权来源"写清楚）不改变上表——它只改变"卡在授权体系里的地位"，不改变"卡在技术上会不会拦住一次写"。

## 四、对后续决策的直接含义

- 想减少卡 → 只能减少**动作次数**，或把动作换到不经工具层的路径。
- 想验证"换连接是否去卡" → 唯一办法是跑一次 canary，本记录不能替代。
- 想让某号零卡且不碰凭据 → 让别的号代写（R7 已对 node-3 的评论这样处理），不是给它配凭据。

# 损坏状态的定点恢复

本说明只用于状态损坏排障，不用于正常拒收、返工或快捷重派。正常重派走 RULES R7 的版本流程。

1. 由 Chen 的直接指令明确节点、精确任务版本键及修复范围；沿用已有授权，不反复索要相同确认。
2. 停止对应 Hook，等待运行实例结束或取得同一把状态锁。
3. 保存当前 seen、pending、HEAD、失败计数和实际脚本版本的成套备份，记录原先不存在的文件，不编造 .bak。
4. 核对精确的 `task_id@vN`、相关 pending 事件与实际接收情况，确定需要修复的那一项。先处理待投递关系，再定点修复，不清空 seen 或整个目录。
5. 对修复后的格式、待投递关系及副本版本进行核对，先 dry_run 再启用；观察真实一轮，确认没有漏投或重复创建任务事件。

备份恢复不得覆盖修复前尚未保存的新记录。无法判断某条 pending 是否已送达时，保留记录并核对接收侧，不能把删除记录当作修复成功。

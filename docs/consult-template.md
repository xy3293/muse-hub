# 咨询模板（C11 附注）

卡住时向 ChatGPT 网页版（主通道）提问，必须按下面模板发问；拿到回答后按过滤规则压缩。

## v2 标准版（默认用这个）

涉及取舍、架构、跨组件的判断，默认用 v2。

```
我在做。
硬约束（必须遵守）：不新增服务器、不新增凭据、不改现有底座、只能用现有数据；。
问题：。

请按下面五节回答，总长 400–600 字，开头第一句就是结论，不要背景复述、不要免责声明、不要"这取决于"：
1) 结论：推荐哪个做法，一句话说清，并给一句话理由
2) 方案对比：给 2–3 个方案，用表格或短行，每个写「做法 / 主要代价 / 需要我放开哪条约束（没有就写"不需要"）」
3) 关键前提：这个推荐成立需要哪些前提（最多 3 条，每条一行）
4) 风险：最可能翻车的一种情况 + 怎么尽早发现它（各一句）
5) 劝退：明确不建议做的 1–2 件事 + 一句话原因

如果你认为我给的某条硬约束正是问题根源，可以在最后加一行「放宽建议」；如果你确实缺关键信息，只写一行「需要：<具体哪一条>」，不要泛泛说需要更多背景。
```

## v1 快问版（降级使用）

只问一个能否/选哪个，答案不影响后续多步决策时用。

```
我在做。
约束（必须遵守）：不新增服务器、不新增凭据、不改现有底座、只能用现有数据。
问题：。
请只输出下面五段，不要任何前言、背景复述、免责声明、"取决于"：
1) 结论：直接给一个推荐做法（一句话）
2) 备选：最多 2 个，每个一行
3) 代价：推荐做法的代价（一行）
4) 风险：最可能翻车的一种情况（一行）
5) 不要做：明确劝退的 1–2 件事（一行）
总共不超过 200 字。
```

## 使用判断

- **默认用 v2**（400–600 字）：涉及取舍、架构、跨组件的判断。
- **v1 降级为"快问"**：只问一个能否/选哪个，答案不影响后续多步决策时用。

## 答案过滤规则（拿到回复后自己做）

- 超过 800 字 → 自己压到 5 行再入报告，原文不进报告；
- 出现"建议咨询专业人士/法律/合规"、泛泛的"取决于"→ 换问法重问一次（明确说"我已经有授权，只需要技术取舍，不要合规建议"）；
- 若它拒答或绕圈 → 降级到 Codex，并在报告里记一句"主通道未给出可用方案"。
- 若 v2 与 v1（或长文版）结论不一致 → **以 v2 / 长文版为准**，并把"压缩会导致方案降级"这件事记一笔。

## 写进报告的口径

咨询记录只写三行：**问了什么（一句）→ 得到什么结论（一句）→ 你怎么定的（一句）**。不要贴长回答，不要贴对话原文。

## 边界

- 模板里的约束（不新增服务器/凭据、不改底座、只用现有数据）是系统真实约束，每次提问都带上。
- 咨询不贴凭据、token、私钥、真实账号、客户数据；不上传整份仓库文件。C1 不变。

## 备注：压缩会导致方案降级（实例）

2026-11-16 Tower 访问：长文版 GPT 推荐"修 Tailscale 入站 + Serve/Caddy 做实时访问"；v1（200 字）版缩成"VM 定时生成静态 HTML、经私有 GitHub 同步、Chen 下载后本地打开"，结论质量掉了（静态快照非实时）。教训：不要为了短而牺牲结论质量；默认用 v2。
